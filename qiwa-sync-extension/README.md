# إضافة كروم — مزامنة قوى (جسر)

مزامنة **كل** منشآت قوى بضغطة واحدة. تمرّ الأداة على كل منشأة تلقائيًا (تبدّل السياق
داخليًا) وتجلب **الموظفين التفصيليين + التأشيرات + ملفات المنشأة + النطاقات …** معًا،
وتكتبها في قاعدة بيانات جسر.

## لماذا إضافة وليست بوكماركت؟

قوى تعزل كل واجهة برمجية على نطاقها الفرعي (CORS):

| البيانات | النطاق |
|---|---|
| الموظفون التفصيليون | `employee-management-api.qiwa.sa` |
| عدّاد الموظفين + ملف المنشأة | `establishment-file-api.qiwa.sa` |
| التأشيرات | `api.qiwa.sa` / `dashboard` |

البوكماركت يعمل على **صفحة واحدة**، فالمتصفح يمنعه من مناداة بقية النطاقات — فتجيب
مزامنة واحدة ناقصة (لهذا كان كرت الموظفين يختفي). خدمة الـService Worker في الإضافة —
بفضل `host_permissions` — تصل **كل** نطاقات `*.qiwa.sa` في تشغيلة واحدة، وترسل كوكيز
جلسة نفاذ الحيّة تلقائيًا. لا خادم، لا بوت، لا فتح كل منشأة.

## التثبيت (مرة واحدة)

1. افتح كروم على `chrome://extensions`.
2. فعّل **«وضع المطور / Developer mode»** (أعلى اليمين).
3. اضغط **«تحميل غير مُحزَّمة / Load unpacked»** واختر مجلد
   `qiwa-sync-extension` هذا.
4. سيظهر أيقونة الإضافة في الشريط. ثبّتها (Pin) لتصل لها بسرعة.

## الاستخدام

1. افتح بوابة قوى وسجّل الدخول عبر **نفاذ** (كالمعتاد).
2. اضغط أيقونة الإضافة → **«مزامنة كل المنشآت»**.
3. تظهر رسائل التقدّم في النافذة: `مزامنة شاملة: X/Y · تم … · متخطّى …`.
   اتركها تكمل — 300 منشأة قد تأخذ عدة دقائق.
4. ارجع لصفحة المنشأة في جسر — يظهر كرت الموظفين التفصيلي والتأشيرات لكل منشأة.

تبقى مسجّلًا في قوى طبيعيًا؛ عند انتهاء الجلسة تُعيد الدخول عبر نفاذ ثم تضغط الزر مجددًا.

## التحقق من الجلسة

قبل بدء المسح تتحقق الإضافة من جلسة قوى (نداء `GET /context/company`). إذا لم تصل
الجلسة تظهر:

> ❌ لم تصل جلسة قوى — افتح قوى وسجّل الدخول عبر نفاذ ثم أعد المحاولة.

كوكي جلسة قوى مضبوط `SameSite`، فلا يُرسَل تلقائيًا من سياق الإضافة. لذلك قبل كل مسح
تقرأ الإضافة كوكيز قوى عبر `chrome.cookies` (تشمل HttpOnly) وتحقنها في ترويسة `Cookie`
عبر قاعدة `declarativeNetRequest` مقصورة على طلبات الإضافة فقط (`tabId -1`) — فلا تمسّ
تبويباتك. هذا يتطلب صلاحيتَي `cookies` و`declarativeNetRequest` في `manifest.json`.

## الدخول لقوى من داخل جسر

تبويب **«الدخول لقوى»** في جسر يسجّل الدخول لقوى دون فتح صفحتها يدويًا:

1. تُدخل في جسر **رقم الهوية وكلمة المرور** ← الإضافة تفتح تبويبًا خلفيًا على أصل قوى وتُرسل
   **نفس طلبات قوى** إلى `sso-api.qiwa.sa/session/login` (لا تكتب في النموذج).
2. يصل **رمز التحقق** للجوال ← تُدخله في جسر ← الإضافة تكتبه في نافذة الرمز بقوى.
3. بعد نجاح الدخول يتحوّل التبويب نفسه إلى بوابة قوى (`auth.qiwa.sa`) ويُعرَض لك مسجَّل الدخول.

- الطلبات تُنفَّذ داخل صفحة قوى (أصل `sso.qiwa.sa`) فتصل الكوكيز والترويسات صحيحة تلقائيًا؛
  نقطة النهاية وبنية الجسم وتشفير كلمة المرور تُقرأ حيًّا من `window._config` فلا تتعتّق.
- كلمة المرور **لا تُحفظ** في جسر ولا في الإضافة ولا تُرسل لأي خادم غير قوى.
- إن طلبت قوى شيئًا لا يُؤتمت (اختبار «لست روبوتًا»، تأكيد جهاز جديد…) يُعرَض تبويب قوى
  لتكمله بنفسك، ثم «فتح قوى» من جسر.
- `bridge.js` سكربت محتوى يعمل على صفحة جسر فقط ويمرّر رسائل `qiwa-login:*` لا غير.
  نطاقات جسر في `manifest.json` ← `content_scripts.matches`: الحالي `famous-horse-6af149.netlify.app`
  و`localhost`. **إن تغيّر نطاق جسر فحدّثه هناك.**
- بعد أي تحديث للإضافة: **Reload** في `chrome://extensions` ثم حدّث صفحة جسر.

## التطوير / إعادة التوليد

منطق المسح **ليس** مكتوبًا هنا — يُولَّد من مصدر واحد:
`src/pages/qiwaSyncBookmarklet.js` (الدالة `qiwaSweepBody`). لتحديث الإضافة بعد أي
تعديل على البوكماركت:

```bash
node qiwa-sync-extension/build.mjs
```

يُعيد كتابة `sweep.generated.js` (لا تعدّله يدويًا). ثم في `chrome://extensions`
اضغط **«إعادة تحميل / Reload»** على الإضافة.

## الملفات

| ملف | الدور |
|---|---|
| `manifest.json` | تعريف MV3 + صلاحيات النطاقات |
| `background.js` | الـService Worker: تحقق الجلسة + تشغيل المسح |
| `sweep.generated.js` | **مُولَّد** — منطق المسح الكامل |
| `build.mjs` | يولّد `sweep.generated.js` من البوكماركت |
| `popup.html` / `popup.js` | زر التشغيل وسجل التقدّم |
| `login.js` | الدخول لقوى من جسر: يعيد طلبات SSO (login/OTP) ثم يفتح البوابة |
| `bridge.js` | جسر الرسائل بين صفحة جسر والإضافة |
